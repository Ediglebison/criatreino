Automações Node executadas via `npm run` (ou `npx tsx`): smoke tests HTTP contra um dev server ativo e provisionamento de recursos Stripe. Não fazem parte do bundle do app.

## Summary

- e2e.mjs — smoke E2E via HTTP (login, alunos, geração, revisão, salvar, atribuição, PDF, permissões, SSR, i18n, recuperação de senha); requer `npm run dev` ativo; `BASE` muda o alvo
- test-reset.mjs — zera RateLimit, UsageRecord e PasswordReset entre execuções de teste
- billing-smoke.mjs — assina eventos Stripe sintéticos (HMAC) e valida `/api/billing/webhook`
- billing-checkout-e2e.mjs — checkout real em modo teste contra a API do Stripe; limpa customer/assinatura ao final
- stripe-setup.mjs — cria produtos/preços dos planos (idempotente) e grava `STRIPE_PRICE_ID_*` no `.env`
- stripe-webhook-setup.mjs — recria o endpoint de webhook clássico e imprime o `whsec_`
- stripe-v2-event-dest.mjs — list/create/ping de destinos de evento v2 (Event destinations); signing secret só via `--secret-out`, nunca no stdout
- probe-ai.ts — diagnóstico: uma chamada real ao provedor de IA fora do Next
- check-i18n.mjs — verifica paridade de chaves entre `messages/pt-BR.json` e `messages/en-US.json`

## Constraints

- Os smoke tests de billing e E2E MUST rodar contra um servidor já iniciado; eles não sobem servidor próprio.
- Scripts Stripe MUST ter `STRIPE_SECRET_KEY` no ambiente ou no `.env`.
- Signing secrets Stripe MUST sair apenas para arquivo (`--secret-out`, permissão 600) — nunca no stdout, log ou argv.
